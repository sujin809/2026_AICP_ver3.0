# 뉴스 재크롤링 계획 및 결정사항

> 보존 구분: 과거 뉴스 준비 provenance. 현재 실행·정책 정본이 아니다.

> 작성: 2026-07-24 · TwinMarket RN Community AB 실험(삼성전자, 커뮤니티 on/off)용 실뉴스 파이프라인 재구축

## 배경 (왜 다시 하나)

기존 뉴스 원본(`data/samsung_news_raw.pkl`)에서 문제 발견:
- **소스 혼재**: "경제" 카테고리에 매경(mk)뿐 아니라 한경(hankyung)이 섞임 (한경 2,483건)
- **본문-스침 노이즈**: 섹터가 `searchField=all`(본문 전체 검색)이라 반도체를 스치기만 한 기사(로봇·리튬 테마 등)까지 유입
- **비관련 뉴스**: 거시경제 카테고리에 산나물·연말정산·농업 등 삼성전자와 무관한 뉴스 다수 (경제 244건 중 ~96건 무관)
- **수정시각(dateModified) 없음**: 현재 데이터엔 최초 발행시각만 있음
- **의도한 3버킷 설계와 불일치** + 출처 불명(현 스크래퍼와 다른 과정으로 생성된 정황)

→ **처음부터 새로 크롤링**하기로 결정 (기존 pkl은 백업/기준으로 보존, 현재까지 원본 미변경 확인됨)

## ✅ 확정된 결정사항

### 1. 소스: 매일경제(mk) 단일
- 한경(hankyung) 제외
- 원 의도가 mk-only였는데 반영이 안 돼 한경이 섞였던 것이 문제였음 → 바로잡음

### 2. 뉴스 3버킷 및 소싱 방식

| 버킷 | 소싱 방식 |
|---|---|
| **삼성전자** | 키워드 검색 — **`"삼성전자"`, `"삼전"`, `"갤럭시"`** (3개, URL 중복제거). **검색 범위 = 제목 ∪ 본문** ✅ 확정 |
| **반도체** | 매경 **기업 > 반도체·전자** 섹션(`/news/business/semiconductors-electronics`)에서 해당 기간 전문 크롤링 ✅ 확정 |
| **거시경제** | 매경 **경제** 하위섹션 — **경제정책(`economic-policy`) + 지표(`business-index`) + 무역(`trade`)** 전문 크롤링. **생활경제(`living-economy`) 제외** ✅ 확정 |

### 3. 기간
- **크롤링 대상: 2026-02-01 ~ 2026-06-30** (넉넉히, 실험창 + 버퍼 커버)
- **실험 창(이번 시행): 45거래일 (2026-02-27 ~ 2026-05-04)** ✅ 확정
  - 45거래일이 authoritative (이전 "47일"은 뉴스 발행일 수 착오). full(2/27~6/1)은 이번 시행에서는 미사용

### 4. 수정시각(dateModified) 기준
- 각 기사에서 `datePublished` + `dateModified` 모두 캡처
- **노출 기준 시각(effective) = max(발행, 수정)** — 수정 버전이 확정된 시점부터 노출
- **`|수정 − 발행| ≤ 12시간` 필터** 적용
  - 목적: 시점 정합/관련성 (너무 늦게 수정된 기사의 본문은 실험 당시 버전과 다를 수 있음)
  - ⚠️ 12h는 **안전(누출)장치가 아님** (아래 6번 참고)

### 5. DB 구조
- **전문 DB** (새 raw): `body`(전문) + 전체 메타(title, date/time, category, source, url, published_at, modified_at) 저장 — **전문 반드시 포함**
- **요약 DB**: 별도 파일로 생성 (전문 DB에서 **qwen3.5-flash**로 요약) — 규격은 아래 5-1 참조
- **에이전트 노출**: depth 정책대로 (D0=제목, D1=제목+요약, D2=+검색). **전문은 저장·해시·분석·누출검토용** (옵션 A)

### 5-1. 요약 생성 규격 ✅ 확정

  - ※ 요약문은 D1/D2 에이전트가 **실제로 읽는 텍스트**이므로, 요약 모델·프롬프트도 **입력 provenance**로 취급
  - ※ RN 실험의 qwen 모델 pin·reasoning-off 제약과는 무관(데이터 준비 단계)

### 5-2. 일별 뉴스 선정 규칙 ✅ 확정

- **단위 ✅ 확정: 결정 턴당 20건** (am 20 + pm 20 = **하루 40건**)
- **버킷 쿼터**: **삼성전자 10 / 반도체 6 / 거시경제 4** (기존 5:3:2 비율 유지, 2배)
  - ⚠️ **실측 경고**: 반도체는 턴당 가용이 평균 **2.7건**(중앙 2, 92개 윈도우 중 86%가 6건 미만)이라, 보충 없음 정책상 **쿼터 6을 거의 못 채움**. 실제 노출은 삼성 ~10 + 반도체 ~2.7 + 거시 ~3.8 ≈ **턴당 16~17건**이 되고 **구성비가 삼성 쪽으로 크게 기움**
  - ✅ **결정(A)**: 위 쏠림을 **그대로 수용**한다. 쿼터는 10/6/4로 두되 가용량이 적으면 그만큼만 노출하고, **논문에는 "설계 쿼터"가 아니라 "실제 노출 분포"(버킷별 턴당 노출 수의 min/중앙/평균)를 보고**한다.
  - (반도체 풀 확장을 위해 키워드 검색을 섞는 방안(B)은 제거했던 노이즈가 재유입되므로 채택하지 않음)
- **선정 방식**: 각 버킷 풀에서 **seed 고정 균등 무작위 추출** (importance 점수 **미사용**)
- **부족분 처리 ✅ 확정: 보충하지 않는다 (빈칸으로 둠)**
  - 버킷 가용량이 쿼터보다 적으면 **가용한 만큼만 노출** (다른 버킷 기사로 메우지 않음)
  - 근거: 버킷 구성비 왜곡 방지 → *"버킷당 최대 N개, 가용량이 적으면 그만큼만"* 으로 정직하게 기술 가능. 양 arm이 동일 뉴스를 보므로 AB 대조에는 영향 없음
  - ⚠️ **코드 변경 필요**: 현행 `news_agent._select_daily`는 부족분을 남은 기사에서 무작위 보충함 → **해당 보충 로직 제거**
  - 결과적으로 **턴별 노출량이 변동**됨 → 논문에 실제 노출량 분포를 보고
- **버킷 중복 기사**: URL 기준 중복제거 후, 대표 버킷은 **삼성전자 > 반도체 > 거시경제** 우선순위로 배정 (소속 버킷 전체는 `buckets` 필드에 기록 보존)

**랜덤을 택한 근거** (연구 목표 = 시장 시뮬레이션 성공 → 가짜뉴스 효과 관찰):
1. **가짜뉴스 처치는 선정과 무관하게 보장** — fake는 추첨 대상이 아니라 `10 real + 1 fake` 추가 슬롯으로 무조건 노출
2. **양 arm이 동일 뉴스**를 보므로 대조(커뮤니티/가짜뉴스) 무결
3. **랜덤이 사실상 중요도 가중으로 작동** — 큰 사건일수록 기사가 여러 건 생성되어 뽑힐 확률이 자연히 상승 (실측: "최태원 AI칩" 2건, "홍해 통항 자제" 3건)
4. **방어 용이성** — 허위정보 연구에서 "뉴스를 유리하게 골랐다"는 의심을 원천 차단. 중요도 점수는 "처치와 상호작용" 의혹을 염
5. 기존 키워드 importance는 **주관성·이중가산 버그·새 버킷과 불일치**로 폐기

*(선택적 보완: 여유 시 중요도 가중 방식으로 소규모 robustness check)*

### 5-3. 풀 정제 필터 ✅ 확정 (크롤 완료 후 적용, 2026-07-24)

전문 크롤 완료 후 실측에서 두 종류의 노이즈가 확인되어, **선정 단계 이전에** 풀 자체를 정제한다.
두 필터 모두 **양 arm에 동일하게 적용**되므로 AB 대조에는 영향이 없다.

**(1) 본문 길이 필터 — 결정론적**
- 본문 **150자 미만 기사 제외** (사진·속보 단신 등 요약 불가 분량)
- 실측 **77건 (전체 6,187건의 1.2%)** — 반도체 27 / 삼성전자 5 / 거시경제 45
- 요약 규격이 "150자 이상 200자 미만"이므로, 원문이 150자 미만이면 **요약이 원문보다 길어지는** 모순이 발생 → 사전 배제

**(2) 삼성전자 관련성 필터 — LLM 분류**
- **대상**: **반도체·거시경제 섹션** 소싱 기사만 (`buckets`에 두 버킷 중 하나 이상 포함).
  **삼성전자 버킷은 제외** — 키워드 검색이므로 정의상 관련성이 보장됨
- **판정**: `keep` / `drop` + 사유 1줄을 기사별로 기록 (`outputs/crawl/relevance.jsonl`, 감사 가능)
- **모델** `anthropic/claude-sonnet-5`, `temperature=0`, 프롬프트 sha256 을 레코드에 기록
- **기준**(프롬프트 전문은 `News_Scraper/filter_relevance.py`):
  - **keep** = 반도체·메모리·파운드리 업황 / 삼성 계열·경쟁사 / 전자·IT·디스플레이 /
    거시금융 지표·정책(금리·중앙은행·환율·외환보유액·**통화량·유동성**·물가·유가·수출입·경상수지·성장률·고용·증시수급·**금 등 안전자산**) /
    **관세·통상은 품목 무관하게 전부** / 반도체·수출·기업 관련 정부 정책 / 공급망
  - **drop** = 사회·복지·인구 이슈 / 개인 생활물가·생활정보 / 문화·예술·스포츠·연예 /
    **항공·여행업**(항공사 실적·노선·여객·항공권·공항 운영·해외여행 수요) /
    개별 부동산 생활정보 / 정책 내용 없는 인사·정치공방 / 지역행사·사회공헌·인물 미담
  - **판단 원칙: 기본값 keep, 명확히 무관할 때만 drop** (보수적 — 정보환경을 과도하게 깎지 않기 위함)
- **사전 검증**: 동일 40건 표본으로 2회 판정.
  초안(v1)은 통화량·관세·중앙은행 금매입을 잘못 drop → 위 keep 목록에 명시 추가(v2).
  v2에서 오판 3건 전원 교정, 역방향 오류 0건, 제외율 **50% → 42.5%**
- **항공 항목(v3) 검증**: 제목에 항공/공항이 포함된 9건 전수 판정.
  진짜 항공업계 기사 1건만 drop, **젠슨 황 방한(공항 입국)·환율(공항 환전)·광주 軍공항 반도체 산단·
  MLCC(`M-LCC` 문자열 오탐)는 전부 keep** 유지 확인.
  → **문자열 매칭이 아니라 내용 기반 판정이어야 하는 근거**(키워드 삭제 시 반도체 핵심 기사가 소실됨)

> ⚠️ 이 필터는 **7월 23일 이전의 "추가 관련성 필터 없음" 방침을 대체**한다.
> 변경 사유: 섹션 브라우징 특성상 거시경제 섹션에 시장과 무관한 사회·생활 기사가 다량 포함됨이 실측으로 확인됨.
> **결과를 보고 기준을 조정하지 않는다** — 기준은 위와 같이 사전 고정하고, 전량 판정 결과를 그대로 적용한다.

### 6. 안전(정보 누출 방지)
- **핵심 = effective-time gating**: 수정시각 기준으로 노출 → 본문 내용 ≤ 수정시각 ≤ 노출시각 → 미래정보 불가
  - 단, "dateModified가 진실하다"는 **검증 불가한 가정**에 의존 (크롤링으론 무엇이 언제 수정됐는지 알 수 없음)
- **12h 규칙 = 안전장치 아님** — 시대착오/관련성 방지용
- **내용 기반 누출검토가 최종 백스톱**: 에이전트-노출 텍스트(제목/요약)에 확정 EOD 수치(당일 종가·최종 순매수 등) 있으면 배제

## 🔧 기술 메모

- **섹션/검색 페이징은 Playwright 필수**: mk 더보기가 Cloudflare + JS(`_CP` AJAX)라 requests 직접 페이징 불가. (기사 **개별 페이지**는 requests로 접근 가능 → 전문·JSON-LD 추출은 requests 사용)
- **⚠️ Cloudflare 봇 감지 회피 필수 (실측)**: 아래 없으면 첫 더보기 클릭부터 `TimeoutError`
  - 브라우저 컨텍스트에 `user_agent` + `viewport` + `locale="ko-KR"` 지정
  - 페이지 로드 후 ~3초, 클릭 전 ~0.8초, 클릭 간 ~1.5초 딜레이
- **✅ 섹션 페이징 검증 완료**: 반도체·전자 섹션 더보기 40회 → 410건, 2026-06-04까지 도달. 섹션 총 6,291건이라 **2026-02 도달 가능**. 속도 ≈ 클릭당 10건, **~1.25일/클릭**
- **✅ 반도체 1주치 E2E 테스트 성공**(07-14~20): 41건 / **전문 41/41(100%)** / dateModified 16건(39%) / 12h 통과 40건. 내용은 반도체·전자 중심(가전·스마트폰·디스플레이 포함)
- **`scrape_mk.py`에 dateModified 캡처 반영 완료** (`get_json_ld_modified_at`)
- **예상 규모**: 반도체 ~7~8건/일(≈1,100건) · 삼성전자 ~20건/일(≈3,000건) · 3버킷 합계 **~5,000건**, full 크롤 **~2~3시간**
- **✅ 크롤러 스크립트 완성**: `News_Scraper/mk_crawler.py` (`section` / `search` 두 모드, 재개 지원, JSONL 저장)
  - 레코드 필드: `url, title, body, published_at, modified_at, effective_at, date, time, gap_hours, keep_12h, source, scraped_at`
- **⚠️ mk 검색 특성**: `startDate == endDate` 면 **0건** 반환 → 날짜 범위를 반드시 벌려서 조회
- **⚠️ 자매지 기사 일부**(예: "매일경제 게임진")는 템플릿이 달라 JSON-LD/본문 추출 실패 → `date=null`로 저장되어 구간 필터에서 자연 제외 (표본상 ~1/7)
