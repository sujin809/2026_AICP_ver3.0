## 동작 프로세스

### Phase 1: 준비 단계

```
1. 폴더 구조 파악
   - ls -la [semiconductor_split 폴더]
   - 총 파일 수 확인
   
2. 필터링 기준 로드
   - FILTERING_CRITERIA.md 읽기
   - 핵심 기준 정리
   
3. 배치 계획 수립
   - 파일을 5개씩 그룹화
   - 배치별 일정 계획
```

### Phase 2: 워커 에이전트 호출

**배치 구성 예시:**
```
Batch 1: 001.json, 002.json, 003.json, 004.json, 005.json (5개 에이전트 동시)
Batch 2: 006.json, 007.json, 008.json, 009.json, 010.json (5개 에이전트 동시)
...
```

**각 워커 에이전트에게 전달할 정보:**
- 처리할 파일 경로 (하나씩)
- 필터링 기준 (간단히 정리)
- 요약 글자 수 요구사항 (150-200자)
- 검증 테이블 포함 요청

### Phase 3: 결과 수집 및 검증

각 에이전트 완료 후:
```
1. 처리 결과 확인
   - 파일명
   - 총 항목 수
   - 검증 테이블

2. 품질 검증
   - 모든 항목의 요약 글자 수 확인
   - 필터링 판정의 일관성 확인
   - 이슈 사항 기록

3. 재작업 필요 여부 판단
   - 글자 수 부족/초과 항목
   - 판정 기준 미충족 항목
   - 수정 후 재검증
```

### Phase 4: 최종 마무리

```
1. 전체 통계 집계
   - 총 파일 수: 50개
   - 총 항목 수: X개
   - KEEP(Y) 항목: X개
   - DROP(N) 항목: X개

2. 완료 보고서 생성
   - 배치별 처리 현황
   - 이슈 사항 요약
   - 검증 결과

3. 최종 확인
   - 모든 파일 처리 완료
   - 모든 항목 검증 완료
   - 데이터 무결성 확인
```

## 워커 에이전트 프롬프트 템플릿

각 워커 에이전트를 호출할 때 다음 정보를 포함하세요:

```
당신은 뉴스 데이터 처리 워커 에이전트입니다.

**작업:**
[파일 경로]/[파일명].json 파일을 열어서 각 뉴스 항목의:
1. "요약": 150~200자 정확하게 작성 (공백 포함)
2. "필터링 여부": Y 또는 N 판정

**필터링 기준:**
- Y(KEEP): 반도체·전자, 거시금융, 관세·통상, 정부정책, 공급망, 삼성 관련
- N(DROP): 사회·복지, 생활물가, 문화·스포츠·연예, 항공·여행, 부동산, 정치·인사, CSR
- 의심 사항은 Y 선택

**필수:**
1. 각 요약 글자 수를 정확히 계산 (150~200자 범위 검증)
2. 검증 테이블로 결과 제시
3. 파일 업데이트 후 완료 보고

**출력:**
- 처리 완료 파일: [파일명]
- 총 항목 수: [숫자]
- 검증 테이블
- 이슈 사항
```

## 동시 호출 관리

### 제약사항
- **최대 5개 에이전트만 동시 호출 가능**
- 6번째 이상은 대기 후 이전 배치 완료 후 호출

### 배치 실행 전략

**Batch 1** (즉시 실행)
- 파일 001.json → 에이전트 1
- 파일 002.json → 에이전트 2
- 파일 003.json → 에이전트 3
- 파일 004.json → 에이전트 4
- 파일 005.json → 에이전트 5

**Batch 2** (Batch 1 완료 후)
- 파일 006.json → 에이전트 6
- 파일 007.json → 에이전트 7
- ... (동일 방식)

## 이슈 처리 가이드

### 글자 수 문제
- **150자 미만**: 에이전트에게 재작성 요청
- **200자 초과**: 에이전트에게 축약 요청
- 재작성 완료 후 재검증

### 필터링 판정 문제
- **기준 미충족**: 근거 확인 후 에이전트와 협의
- **판정 불일치**: 필터링 기준 명시 후 재판정 요청
- 최종 판정은 오케스트레이터가 승인

### 기타 이슈
- 본문 누락, 제목 오류 등 데이터 오류 기록
- 해결 불가능 사항은 최종 보고서에 명시
